# PRD: prd-lint — Mechanical PRD Gate

## 1. Overview

**Problem:** PRDs reach task-breakdown from four authors (humans, Claude, pi's create-prd skill, gap-to-prd) with no mechanical check that the compiler-contract fields exist; a missing same-line `Target Files` or absent `Priority` silently degrades into targetless or mis-ordered beads discovered only mid-run.
**Solution:** `tools/prd-lint`, a deterministic linter enforcing the create-prd compiler contract exactly as `analyzer.mjs` parses it, wired as a fail-open preflight into task-breakdown's CLI — one chokepoint that catches every author.
**Success Metrics:**
- A doctrine-compliant PRD (e.g. `docs/PRDs/per-phase-model-routing-20260717.md`) lints clean.
- A PRD whose `Target Files` is a bullet list (the old gap-to-prd format) fails with a violation naming the FR and the fix.
- task-breakdown refuses to decompose a PRD with lint errors; boxes without the binary are unaffected.

## 3. Functional Requirements

### FR-001: prd-lint Tool
**Type:** fr
**Priority:** P1

**Target Files:** `tools/prd-lint/main.go`, `tools/prd-lint/main_test.go`, `tools/prd-lint/go.mod`

New standalone tool (own `go.mod`, module `github.com/haulmatic-dev/hydra/tools/prd-lint`, standard library only). CLI: `prd-lint <prd.md> [--json]`. It scans requirement blocks — a block starts at a heading matching `^#{2,3}\s+(FR|US|NFR)[-A-Za-z0-9]*-?\d*` and ends at the next such heading — and applies these rules, each violation carrying the requirement ID, line number, rule code, and message:

| Rule | Applies to | Check |
|------|-----------|-------|
| `R1-type` | every requirement | has a `**Type:**` line with a value from: fr, us-light, us-heavy, us-integration, nfr-verification, nfr-config |
| `R2-priority` | every requirement | has `**Priority:**` matching `(?i)p[0-3]` |
| `R3-target-files` | fr, nfr-config, us-light, us-heavy | has `**Target Files:**` with non-empty same-line content (the exact condition `analyzer.mjs:121` requires); a bare `**Target Files:**` line followed by bullets is the canonical violation, message matching `/same-line/` with the exact literal string `Target Files must be same-line (bullet lists are not parsed)` |
| `R4-acceptance` | every requirement | has an `**Acceptance Criteria:**` section with at least one `- ` bullet before the block ends |
| `R5-unique-id` | whole file | no requirement ID appears twice |
| `R6-aggregates` | us-* | has an `**Aggregates:**` section |
| `R7-refs` | whole file | every ID referenced in `Depends On`/`Aggregates`/`Verifies`/`Reads From` bullets exists in the file |
| `R8-commands` | nfr-config | has `**Test Command:**` and `**Build Command:**` same-line values |

Output: human-readable one violation per line (`<file>:<line> <rule> <id>: <message>`) by default; `--json` emits `{"passed": bool, "violations": [{"rule","id","line","message"}]}`. Exit codes: 0 = clean, 1 = violations, 2 = configuration error (missing/unreadable file). A file with zero requirement headings is a violation (`R0-empty`, message with the exact literal string `no requirement headings found`) — an empty PRD must not pass.

**Acceptance Criteria:**
- Linting a minimal valid PRD fixture (one FR with all fields, one US with Aggregates, NFR-SYS) exits 0 with `passed: true`
- A fixture whose FR has `**Target Files:**` on its own line followed by `- ` bullets yields exactly one `R3-target-files` violation whose message contains the exact literal string `Target Files must be same-line (bullet lists are not parsed)`
- A fixture missing `**Priority:**` on one FR yields one `R2-priority` violation naming that FR's ID
- A fixture where US-001 aggregates `FR-009` but no `FR-009` exists yields one `R7-refs` violation
- A fixture with two `### FR-001` headings yields one `R5-unique-id` violation
- A fixture with no requirement headings exits 1 with an `R0-empty` violation whose message contains the exact literal string `no requirement headings found`
- `--json` output on a failing fixture parses as JSON with `passed` equal to `false` and a non-empty `violations` array
- `prd-lint` with no arguments exits 2 and stderr matches `/usage/i`
- `go build ./...` exits 0
- `go test ./...` exits 0

**Depends On:** —

### FR-002: task-breakdown Preflight
**Type:** fr
**Priority:** P1

**Target Files:** `pi-config/skills/task-breakdown/cli.mjs`

**Reads From:**
- FR-001: prd-lint Tool

In `pi-config/skills/task-breakdown/cli.mjs`, before constructing `TaskBreakdownRunner` (i.e. before any tasks can be created): resolve a `prd-lint` binary in this order — `$HYDRA_TOOLS_DIR/prd-lint/prd-lint`, `<cwd>/tools/prd-lint/prd-lint`, `/opt/dev-tools/components/hydra/tools/prd-lint/prd-lint`, then `prd-lint` on PATH (mirroring the analyzer's `runTool` resolution). Behavior:

- **Binary not found → fail-open:** proceed with decomposition; in human mode print one line `prd-lint not found — skipping preflight`, in `--json` mode emit `{"type":"lint:skipped"}`.
- **Binary found, exit 0:** proceed (emit `{"type":"lint:passed"}` in JSON mode).
- **Binary found, exit 1:** do NOT run the runner. Human mode: print the linter's output and exit 1. JSON mode: emit `{"type":"error","code":"PRD_LINT_FAILED","error":<first 2000 chars of linter output>}` and exit 1.
- **Escape hatch:** a `--no-lint` flag (added to `parseArgs`) skips the preflight entirely.
- Linter crashes (exit ≥2 or spawn error) are treated as fail-open with a warning, never blocking decomposition.

Use `child_process.spawnSync` with the PRD's absolute path as the only argument plus `--json`.

**Acceptance Criteria:**
- `node --check pi-config/skills/task-breakdown/cli.mjs` exits 0
- With `HYDRA_TOOLS_DIR` pointing at a temp dir containing a stub `prd-lint/prd-lint` script that exits 1 printing `{"passed":false,"violations":[{"rule":"R2-priority","id":"FR-001","line":10,"message":"missing Priority"}]}`, running `node cli.mjs <any-prd> --json` exits 1, stdout contains an event with `"code":"PRD_LINT_FAILED"`, and no `task:created` event is emitted
- Same setup with a stub that exits 0: the runner starts (a `workflow:start` or `validation:start` event is emitted)
- With no resolvable `prd-lint` binary, behavior is identical to today except one `lint:skipped` event/line
- `--no-lint` bypasses the preflight even when a failing stub is resolvable
- The exit-2-crash stub does not block: decomposition proceeds with a warning line matching `/prd-lint/`

## 5. Technical Considerations

### Architecture
- **One chokepoint.** Linting inside task-breakdown's CLI catches every author path (human/Claude/pi/gap-to-prd and the compliance cycle's `createGapBeads`, which invokes the same `cli.mjs` — `internal/core/compliance_cycle.go:340-355`). Linting in each author would be four implementations.
- **Fail-open by design.** The linter is an upgrade, not a dependency: boxes without the binary keep working. The compliance cycle inherits the gate automatically once the binary is deployed.
- **Rules mirror the parser, not an ideal.** Each rule checks exactly what `analyzer.mjs` needs to parse; the linter must never demand syntax the parser doesn't read (that would fork the doctrine).

### Technology
- Go standard library for the linter; `child_process.spawnSync` in the mjs preflight (no new npm dependencies).

### Implementation Map

| Requirement | Target Files | Type | Depends On | Chain |
|-------------|-------------|------|------------|-------|
| FR-001 | `tools/prd-lint/main.go`, `main_test.go`, `go.mod` | fr | — | — |
| FR-002 | `pi-config/skills/task-breakdown/cli.mjs` | fr | Reads From FR-001 | — |
| US-001 | — | us-integration | FR-001, FR-002 | — |
| NFR-SYS | — | nfr-verification | FR-001, FR-002 | — |

### Edge Cases
- Headings like `### FR-001a:` (forbidden by doctrine): flagged under `R5-unique-id` when the base ID collides, otherwise accepted as a distinct ID (the doctrine ban on a/b splits stays a create-prd concern; the linter checks parseability, not style).
- `NFR-SYS` (no trailing number) must be recognized as a requirement heading.
- Requirements inside fenced code blocks (template examples embedded in a PRD): lines within ``` fences are skipped entirely.
- CRLF line endings: normalized before matching.

### Constraints
- The gap-to-prd output (after `docs/PRDs/gap-to-prd-doctrine-20260723.md` lands) must lint clean — run its golden fixture through the linter as a cross-check during dogfood verification of THIS PRD (sequencing: gap-to-prd doctrine dogfood runs before this one).
- No behavior change to `runner.mjs`/`analyzer.mjs` — the preflight lives entirely in `cli.mjs`.

## 7. Research Insights

### Codebase Findings
- Parser source of truth: `pi-config/skills/task-breakdown/analyzer.mjs` — requirement headings, priority (`:109`), same-line target files (`:121`), reads-from (`:141`), test/build commands (`:161-184`), Verifies/Aggregates sections.
- `cli.mjs` currently constructs the runner immediately after arg parsing (`cli.mjs:82-91`) — the preflight slots in between.
- Binary resolution precedent: `runTool` in `tools/hydra-compliance-analyzer/main.go:159-226` (project-vendored → `$HYDRA_TOOLS_DIR` → `/opt/dev-tools/components/hydra/tools/...`).
- The compliance cycle calls this same `cli.mjs` for gap PRDs (`internal/core/compliance_cycle.go:344`), so the gate covers auto-generated PRDs with zero extra wiring.

### Historical Patterns
- Targetless beads were a real failure class (`docs/PRDs/scope-gate-targetless-beads-20260715.md`); the scope gate catches them late — this linter catches them before a single bead exists.
