## 1. Read this first — how to not be wrong about this system

### 1.1 Anchor every log grep on the daemon's own prefix

Worker stdout and stderr are echoed into the same file as the daemon's log, prefixed with `[Worker:<bead>]`. A plain grep for `concurrent request limit` will count the daemon's own summary and every worker echo, giving you a multiple that does not mean "N beads hit this".

```bash
# count daemon-level events only
grep 'concurrent request limit' /var/log/hydra/hydra-error.log | grep -vE '^[0-9/]+ [0-9:]+ \[Worker:' | wc -l

# count worker-level echoes only
grep 'concurrent request limit' /var/log/hydra/hydra-error.log | grep -E '^[0-9/]+ [0-9:]+ \[Worker:' | wc -l
```

If the two numbers differ, your previous number was contaminated.

### 1.2 `grep -c` exits 1 on zero matches

Do not write `count=$(grep -c x f || echo 0)`. It produces `"0\n0"`, and `[[ $count -eq 0 ]]` will throw. Use `grep -c x f 2>/dev/null || true` and then handle the empty string, or use `grep -c x f | { read c; echo ${c:-0}; }`.

### 1.3 Verify with a marker, not just freshness

`scripts/verify-deploy.sh` defaults to a 10-minute window. After the initial restart that window expires and the script reports the binary as "stale" even though it is the correct deployed binary. Always verify with the build timestamp and a marker string that is unique to the change:

```bash
cd /opt/dev-tools/components/hydra
./scripts/verify-deploy.sh "$(stat -c %Y /opt/dev-tools/var/hydra/bin/hydra)" "ReapStale" daemon
./scripts/verify-deploy.sh "$(stat -c %Y /opt/dev-tools/var/hydra/bin/worker)" "PI_CODING_AGENT_SESSION_DIR" worker
./scripts/verify-deploy.sh "" "shouldPauseForCongestion" daemon
```

### 1.4 Never restart the daemon with workers in flight

Check before any restart:

```bash
scripts/run-lock.sh describe     # should print "no active run"
pgrep -af 'var/hydra/bin/worker' | grep -vE 'pgrep|rtk'
```

If either shows work, wait or mark beads failed manually before restarting.

## 2. What is live now (2026-08-03)

### 2.1 Park-and-resume on provider congestion

A worker that hits a **concurrent-request-limit / 429 / 529 / 500 / 504** error no longer exits. It parks the live pi session, reports `state: parked` to the daemon, and resumes the same session after a 30 s → 5 min exponential backoff (cap 60 min). Parked time does not count toward the worker lifetime cap, and parked workers are not killed by wall-clock time.

The worker lives in `cmd/worker/main.go` → `parkLoop` → `park.go`.

Classification is **marker-first**: the string `concurrent request limit`, `usage limit`, `billing_error`, etc. decides the tier before the HTTP status or `type` field, because Kimi's `type` values lie (`429` can be `rate_limit_error`, `403` can be `permission_error` or `access_terminated_error`). OpenRouter credit exhaustion arrives as HTTP 402 `billing_error` and matches the quota markers → exit 6 → provider-breaker spawn freeze.

### 2.2 Named pi session files

Workers now build a deterministic, file-name-safe session id from the bead id, create a directory under `$HYDRA_HOME/sessions`, and pass `--session` and `--session-dir` to pi. The session directory is exported as `PI_CODING_AGENT_SESSION_DIR` and the session id is reported to the daemon registry. A replacement worker (or a daemon restart) can therefore resume the same pi session files instead of starting from zero.

Code: `cmd/worker/main.go` (`buildPiSession`, `buildPiCommand`) and `cmd/worker/session_test.go`.

### 2.3 Verdict-based closure

A worker is allowed to exit only after emitting a `HYDRA_VERDICT` JSON block:

```json
{"done": true, "ac_met": [...], "ac_unmet": [], "files_changed": [...], "verification": [...]}
```

or an `abandon-with-summary` verdict with a `summary` field. If pi stops talking without a verdict, the worker re-prompts in the same session (up to 3 nudges) instead of killing the process.

### 2.4 Daemon-owned SQLite registry

`/opt/dev-tools/var/hydra/.hydra/registry.db` is the single source of truth for worker state, heartbeats, park fields, and queued commands. The old `workers.json` is still read by Charon as a fallback during migration, but the registry is authoritative.

Registry GC is live: `Store.ReapStale(cutoff)` removes completed workers and workers whose last heartbeat is older than the cutoff, plus their queued commands. The daemon runs it on startup with a 24-hour cutoff.

### 2.5 Charon liveness and timeouts

- Worker lifetime cap: **2 hours** (`HYDRA_WORKER_LIFETIME_MINUTES`, parked time excluded).
- Activity timeout: **4 minutes** (no output from the worker).
- Park cap: **60 minutes** (`HYDRA_MAX_PARK_MINUTES`).
- Charon hung-kill: **stale heartbeat > 5 minutes**, not wall-clock time. A parked worker with a fresh heartbeat is never killed on time alone.

### 2.6 Pan, the shepherd

`internal/pan` is configured in `/etc/hydra/hydra.yaml` with `shepherd.pan.enabled: true` and a **dedicated MiniMax key** (`provider: minimax`, `model: MiniMax-M2.7`, `api_key_name: MINIMAX_API_KEY`). It is now running against the registry every 60 s and may queue steering commands for the ambiguous tail (parked-overdue, hung, verdict-missing-past-nudge-cap workers). The deterministic rules still run underneath; Pan is fail-open.

Pan has not yet made an autonomous judgment on this stack. Monitor `/var/log/hydra/hydra-error.log` for `[Pan]` lines and the registry command queue before relying on it.

### 2.7 Scheduler congestion pause

When the registry shows 3+ live parked workers (heartbeat within 10 min), the scheduler pauses new spawns for 5 min. This prevents a provider storm from turning into a pile of parked workers that all compete for the same saturated slots. The gate is fail-open: a missing registry or counter error never blocks the scheduler.

Code: `internal/core/scheduler.go` (`Scheduler.shouldPauseForCongestion`).

### 2.8 `settled_state` auto-shutdown disabled

`/etc/hydra/hydra.yaml` has `settled_state.enabled: false`. The previous default stopped the daemon at idle and delayed parked workers from waking. If you re-enable this, verify that parked workers can still resume after the daemon wakes up.
