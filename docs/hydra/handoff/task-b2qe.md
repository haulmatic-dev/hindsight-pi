## Open edges for the next phase
- `rejectInfraGate` escalation does not write an `infra-reject-` attempt label past the cap (counter frozen at N-1 by design; the `infra-stuck` label is the durable marker) — if operators want the exact count on the bead, extend the escalation branch.
- Output text is accepted by `isInfraGateFailure` but classification is exit-code based (documented in the fn); if a missing-tool signal ever appears with a non-127 exit (e.g. npm ENOENT wrappers), extend the classifier there.
- Signal-death classification uses negative exit codes from `exec.ExitError`; a shell that itself exits negative is not reachable via `/bin/sh -c` today.
